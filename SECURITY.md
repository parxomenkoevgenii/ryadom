# Политика безопасности

«Рядом» — личный чат для устройств в одной домашней сети: Windows-ПК или Android-телефон выступает главным устройством, остальные подключаются к нему напрямую. Приложение не использует аккаунты, облако и внешние серверы.

## Поддерживаемые версии

| Версия | Статус |
| --- | --- |
| 0.1.x | Исправления безопасности выходят только в последней версии линейки. |
| 0.2.x | После выпуска — поддерживаемая линейка. |

Обновляйте приложение на всех устройствах. На Windows сначала выключите старое приложение через значок рядом с часами, затем замените EXE. APK устанавливается поверх предыдущего приложения с сохранением данных.

## Как сообщить об уязвимости

- Используйте **приватный канал GitHub Security Advisories**: <https://github.com/parxomenkoevgenii/ryadom/security/advisories/new>.
- Не открывайте публичные issue с деталями уязвимости, эксплойтами и персональными данными.
- В отчёте укажите: версию и платформу, шаги воспроизведения, ожидаемое и фактическое поведение, оценку влияния. Не прикладывайте переписку, файлы и токены устройств.
- Если приватный канал недоступен, свяжитесь с владельцем репозитория через профиль GitHub и не раскрывайте детали публично до согласованного срока.

Мы постараемся подтвердить получение в течение 7 дней. Публичное раскрытие — после выпуска исправления или по согласованию с автором отчёта.

## Модель угроз и границы

- Приложение рассчитано на **доверенную домашнюю сеть**. В версии 0.1.x передача внутри локальной сети идёт **без TLS и сквозного шифрования** — это известное ограничение, исправление запланировано в 0.2.0 (см. [ROADMAP.md](docs/ROADMAP.md)).
- Устройства в одной сети могут видеть служебную информацию (адреса, имена устройств), необходимую для обнаружения.
- Не считается уязвимостью: доступ к чату при физическом доступе к разблокированному главному устройству; перехват трафика в сети, которая не контролируется владельцем; отключение защиты самим пользователем.
- Уязвимостями считаются: обход аутентификации устройства, несанкционированное подключение, утечка данных за пределы локальной сети, выполнение кода, отказ в обслуживании главного устройства, обход подписи релизов.

## Подпись и проверка релизов

- Манифест `SHA256SUMS.txt` содержит контрольные суммы файлов выпуска.
- Манифест подписывается отделённой подписью OpenSSH (`SHA256SUMS.txt.sig`); публичный ключ и `allowed_signers` — в каталоге [`keys/`](keys/). Windows-сборка подписывается Authenticode (текущий сертификат самоподписанный до покупки OV/EV).
- Подпись манифеста и Windows-сборки станет обязательной начиная с 0.2.0; инфраструктура и ключи уже подготовлены.
- Проверка: `SHA256SUMS.txt` + `.sig` через `ssh-keygen -Y verify`. Инструкция — [docs/RELEASE-SIGNING.md](docs/RELEASE-SIGNING.md).
- Не устанавливайте сборки из непроверенных источников и всегда сверяйте хэши и подпись.

## Обработка данных

Переписка и файлы хранятся только на выбранном главном устройстве. Приложение не собирает телеметрию и не отправляет данные в интернет. Удаление приложения на Android удаляет его данные; на Windows данные находятся в `%LOCALAPPDATA%\Ryadom`.
