# Подробная инструкция — Рядом 0.1.2

[← На главную страницу](../README.md)

Личный чат для ваших устройств в одной домашней сети. Текст, фото, видео и файлы передаются через выбранное главное устройство — **любой Windows-ПК или Android-телефон**. Интернет, аккаунты и внешние серверы не нужны.

## Готовые приложения

**[Скачать выпуск 0.1.2 для Windows и Android](https://github.com/parxomenkoevgenii/ryadom/releases/tag/v0.1.2)** — готовые приложения, исходники и инструкция находятся в разделе Releases.

- `dist/Ryadom-Windows.exe` — Windows 10/11 x64; один переносимый файл, Node.js отдельно не требуется.
- `dist/Ryadom-Android.apk` — Android 8.0+; клиент и главное устройство в одном приложении.
- `dist/Начать здесь.txt` — короткая инструкция.

Обновите приложение на всех устройствах. На Windows сначала выберите **Выключить Рядом** в меню значка рядом с часами, затем замените EXE. APK устанавливается поверх предыдущей версии с сохранением данных: ключ подписи прежний. Не удаляйте Android-приложение перед обновлением.

## Выбор главного устройства

При каждом запуске появляется выбор:

1. На одном устройстве нажмите **Создать чат на этом компьютере / телефоне**.
2. В открытом чате нажмите **Подключить устройство**: там находятся домашний адрес и восьмизначный код.
3. На остальных устройствах нажмите **Найти в сети**, выберите главное устройство и подключитесь по коду. Если поиск ничего не нашёл, введите адрес вручную, например `192.168.1.38:4280`.

Сменить выбор можно в любой момент:

- Windows: **Настройки → Выбрать главное устройство**, либо меню значка рядом с часами → **Выбрать другое главное устройство**. Меню значка доступно и при недоступном старом главном устройстве.
- Android: кнопка **Выбрать главное** над чатом.

Если вы меняете роль главного устройства, его сервер останавливается, подключённые устройства теряют связь и должны выбрать нового главного. Если меняете роль клиента, работа удалённого чата продолжается. **История остаётся на устройстве, на котором создан чат. Автоматического переноса или объединения историй нет.** При повторном создании чата на том же устройстве его история сохраняется.

## Кабель и Wi-Fi

ПК по Ethernet и телефон по Wi-Fi поддерживаются одновременно. Они должны находиться в одной локальной IPv4-подсети одного роутера. Само различие между кабелем и Wi-Fi не мешает соединению.

Приложение использует физические Ethernet/Wi-Fi-адаптеры, исключает виртуальный адаптер Happ из адресов и ищет главный узел через локальные широковещательные и групповые сообщения. Если роутер не пропускает поиск, подключитесь по адресу вручную.

Если даже ввод адреса не помогает:

1. Проверьте, что главное устройство включено, чат запущен и оно не спит.
2. Подключите телефон к основной домашней сети, а не гостевой. Роутер не должен изолировать Wi-Fi-клиентов друг от друга или от проводной сети. Разные VLAN/подсети этой версией не поддерживаются.
3. На главном Windows-ПК разрешите входящий доступ для **самого `Ryadom-Windows.exe`** в брандмауэре только из доверенной локальной подсети: TCP **4280** для чата и UDP **42800** для поиска. В брандмауэре Windows приложение предложит добавить эти правила само при первом запуске в режиме главного; для стороннего брандмауэра (ESET, Kaspersky) правило добавляется в его настройках — см. раздел «Брандмауэр на главном Windows-ПК». Старое правило для `RyadomHost-…exe` недостаточно: в версии 0.1 входящую связь принимает оболочка Windows.
4. Проверьте ограничения Happ, описанные ниже.

Приложение не меняет настройки сторонних брандмауэров и роутера. Проброс портов в интернет не нужен. Изоляцию, установленную роутером или брандмауэром, программа обойти не может.

## Брандмауэр на главном Windows-ПК

Входящие подключения к чату принимает `Ryadom-Windows.exe`: TCP **4280** (чат) и UDP **42800** (поиск в сети). Если на компьютере включён брандмауэр без правил для приложения, телефон покажет `failed to connect … after 4500 ms`, хотя поиск, интернет и пинг в локальной сети работают.

- **Брандмауэр Windows.** При первом запуске в режиме главного устройства приложение проверяет профили брандмауэра и предлагает добавить входящие правила — только из локальной сети, для текущего EXE. Потребуется подтверждение администратора (UAC). Состояние можно проверить в меню значка Рядом → **Проверить брандмауэр и сеть**.
- **Сторонний брандмауэр** — ESET, Kaspersky и подобные комплексы. Они заменяют брандмауэр Windows: его профили выключены, правила Windows не действуют. Разрешите `Ryadom-Windows.exe` входящие TCP 4280 и UDP 42800 из локальной подсети в настройках этого продукта или пометьте домашнюю сеть как доверенную. Пример для ESET: **Настройки (F5) → Сеть → Брандмауэр → Сети** → ваша домашняя сеть → «Доверенная»; либо **Правила → Добавить**: действие «Разрешить», направление «Входящее», приложение `Ryadom-Windows.exe`, локальные порты TCP 4280 и UDP 42800, удалённые адреса — локальная подсеть.
- **Общедоступная сеть Windows.** В профиле «Общедоступная» брандмауэры по умолчанию блокируют входящие. Параметры Windows → Сеть и Интернет → Ethernet/Wi‑Fi → свойства сети → **«Частная»**.

Быстрая проверка с телефона: откройте в браузере `http://<адрес ПК>:4280/api/health` — при успехе вернётся JSON `{"app":"ryadom",…}`. Приложение не меняет настройки сторонних брандмауэров и роутера; изоляцию клиентов обойти нельзя.

## Happ на обоих устройствах

Версия 0.1 направляет соединения в домашнюю сеть напрямую, без системного HTTP-прокси:

- Windows выбирает физический сетевой адаптер и привязывает к нему исходящие соединения и ответы сервера. Окно чата использует локальный канал связи и отдельный профиль Edge/Chrome без прокси.
- Android выбирает сеть Wi-Fi/Ethernet с признаком `NOT_VPN`; текст, загрузки, видео и события проходят через сокеты этой сети. WebView обращается к локальному шлюзу внутри приложения. При потере домашней сети переключения на VPN или мобильный интернет нет.

**Безусловно обойти запрет самого VPN невозможно.** Если конфигурация Happ или Android блокирует прямые соединения, добавьте Рядом в исключения Happ: раздел проксирования отдельных приложений, режим **Bypass / напрямую**, приложение **Рядом** (`local.ryadom.chat`). На Windows при необходимости исключите **Ryadom-Windows.exe**. Название пункта может отличаться в версиях Happ; после изменения правил переподключите VPN. Остальные приложения могут продолжать работать через Happ.

Android с включённым системным режимом «Блокировать соединения без VPN» может запрещать даже явно выбранную локальную сеть. Это ограничение системы: приложение самостоятельно его не снимает.

Пункт Happ **Allow LAN Connections** разрешает другим устройствам использовать прокси Happ; это другой режим, для Рядом его включать не требуется.

Справка: [Happ — режимы для отдельных приложений](https://github.com/HappDev/happ_su/blob/main/dev-docs/app-management.md), [Android — allowBypass](https://developer.android.com/reference/android/net/VpnService.Builder#allowBypass()), [Android — ограничения VPN](https://developer.android.com/develop/connectivity/vpn), [Windows — выбор сетевого интерфейса](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options).

## Работа в фоне

На Windows закрытие окна не выключает чат. Значок Рядом остаётся рядом с часами: двойной щелчок открывает чат, **Выключить Рядом** завершает работу.

На Android главный узел работает как фоновая служба с уведомлением **Этот телефон главный** и кнопкой выключения. Телефон должен оставаться подключённым к домашней сети. При потере этой сети служба останавливается; после подключения запустите чат снова. Некоторые прошивки ограничивают фоновые приложения — при обрывах во время сна разрешите для Рядом работу без ограничений батареи. Главный телефон расходует больше энергии.

Клиент Android синхронизирует пропущенную переписку при возвращении в чат. Системных уведомлений о новых сообщениях пока нет; служебное уведомление главного устройства не является уведомлением о сообщениях.

## Возможности

- Подключение только по коду; код действует 15 минут, его можно обновить или закрыть приём новых устройств.
- Постоянная история, загрузка предыдущих сообщений, восстановление связи.
- Текст, фото, видео и другие файлы до **512 МБ** каждый, без сжатия оригиналов.
- Несколько вложений, прогресс, повтор неудачной отправки, перемотка видео.
- Перетаскивание файлов и вставка изображений на компьютере.
- Поиск по загруженной переписке, фильтр медиа, имена устройств, статус присутствия и отзыв доступа.

На компьютере Enter отправляет текст, Shift+Enter переносит строку. На сенсорном экране отправка выполняется кнопкой со стрелкой.

Другие устройства могут открыть адрес главного в браузере и подключиться по коду. Такой браузер использует собственные сетевые настройки: прямой канал поверх системного VPN реализован именно в приложениях Windows и Android.

## Данные

Windows хранит сообщения, вложения и ключи в `%LOCALAPPDATA%\Ryadom`: `chat.sqlite` и сопутствующие файлы SQLite, `files`, `host-key`. Для резервной копии выключите Рядом и скопируйте всю папку. Обновление EXE её не очищает.

Android хранит историю своего главного узла и вложения в закрытой папке приложения (`files/host`). Обновление APK сохраняет её, удаление приложения или очистка его данных удаляет историю. Экспорт истории между главными устройствами пока не реализован.

Передача по локальной сети выполняется по HTTP, **без TLS и сквозного шифрования**. Используйте доверенную домашнюю сеть и не сообщайте код посторонним. Поддерживается локальная IPv4-подсеть; IPv6 и соединение через интернет не реализованы.

Предпросмотр зависит от кодеков браузера/Android System WebView. JPEG, PNG, GIF, WebP и распространённые MP4/WebM показываются в чате; неподдерживаемые форматы доступны в оригинале для скачивания.

## Разработка и сборка

Интерфейс не загружает CDN, сетевые шрифты или внешние библиотеки.

```powershell
npm test
npm run build:windows
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-android.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-windows.ps1
```

`npm start` запускает исходный Node-сервер для разработки; физическая привязка к сети и выбор роли требуют Windows-оболочку. Node.js 24+ нужен для исходников, 25.5+ с `--build-sea` — для сборки EXE. Выпуск собран с Node.js 26.13.0 и .NET Framework C# Compiler; оболочка использует Windows Forms, System.Drawing и System.Management.

Android собирается с JDK 21, SDK Platform 35 и Build Tools 36.0.0 без Gradle. Пути можно задать параметрами `-SdkPath` и `-JdkPath`. APK использует системные Android API. JVM-тесты дополнительно скачивают `org.json:json:20240303` из Maven Central с проверкой SHA-256; библиотека в APK не добавляется.

Ключи подписи хранятся **вне репозитория и вне OneDrive** — по умолчанию в `%LOCALAPPDATA%\RyadomSigning` (ключ APK `ryadom.jks` и пароль, сертификат Authenticode, ключ OpenSSH). Путь можно переопределить параметром `-SigningDir` или переменной `RYADOM_SIGNING_DIR`. Релизная сборка APK **не создаёт новый ключ**: если ключа нет, сборка останавливается (для первого локального стенда есть явный флаг `-CreateSigningKey`). Ключ APK нельзя терять — иначе APK не сможет обновиться поверх установленного. Подробности подписи и проверки релизов — в [RELEASE-SIGNING.md](RELEASE-SIGNING.md). Папки ключей, сборок, зависимостей тестов и данных исключены в `.gitignore`.

### Проверка версии 0.1

Один набор интеграционных проверок выполняется для Node-сервера, встроенного Windows-сервера и Android-сервера на JVM. Проверяются подключение по коду, защита Host/Origin, права главного, текст и события, загрузка оригиналов, диапазоны байтов для видео, постраничная синхронизация, сохранность после перезапуска и отзыв доступа. Отдельно проверяются Windows/Android-шлюзы: изоляция сессий разных ролей, передача файла 2 МБ, видео-диапазоны и живые события; смена главного создаёт только локальный сигнал и не выключает удалённый чат.

На этом Windows-ПК при включённом Happ проверены выбор физического Ethernet вместо туннеля, прямая передача TCP и обнаружение в сети. Вручную проверено окно выбора главного устройства. APK собран и подписан; Android-сервер и шлюз проходят интеграционные тесты на JVM. **Физический Android, работа при его активном Happ и передача между двумя отдельными устройствами по Wi-Fi/Ethernet пока не проверены: подключённого телефона нет.**
